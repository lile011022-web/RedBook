# RedBook AI 文案与运营分析设计

## 目标

把 RedBook 从基础运营记录工具升级为“人设驱动的 AI 文案 + 手动数据看板 + AI 运营建议”工作台。

本次实现后，运营人员可以：

- 在 `草稿` 页面选择账号和选题，由 GPT 根据该账号人设生成多版小红书文案。
- 直接复制每版文案的标题、正文、标签和封面文案。
- 暂时隐藏 `素材` 功能入口，减少当前使用干扰。
- 在 `运营分析` 页面手动录入小红书创作中心数据看板指标。
- 用 AI 根据账号人设和数据表现给出实质性运营建议。

## 合规边界

允许做：

- 使用用户本机配置的 OpenAI API Key 调用 GPT。
- 根据 RedBook 中的人设、选题、历史草稿和手动录入数据生成建议。
- 由用户手动登录小红书官方创作中心。
- 由用户手动查看并录入数据看板指标。
- 由用户手动复制文案、手动发布、手动记录结果。

不允许做：

- 自动登录小红书。
- 自动读取或抓取小红书后台页面数据。
- 自动发布、自动点击、自动填表。
- 保存小红书账号密码。
- 使用代理、设备伪装、风控绕过或群控能力。

## OpenAI Key 配置

后端继续通过现有方式读取 OpenAI API Key：

1. 优先读取环境变量 `OPENAI_API_KEY`。
2. 如果环境变量为空，再读取 RedBook 设置表中的 `openai_api_key`。

软件不在 UI 中显示真实 key。测试和日志不能打印 key。

## 草稿页面：人设驱动 GPT 文案

### 输入

运营人员在 `草稿` 页面选择账号后输入：

- AI 主题
- 生成数量：默认 3 条，可选 1-5 条
- 可选补充要求：例如“更生活化”“突出价格优势”“适合新手妈妈”

后端读取该账号的人设：

- 账号定位
- 内容方向
- 语气风格
- 禁用词
- 发布频率

### 输出

GPT 返回多版文案，每版包含：

- 标题
- 正文
- 标签
- 封面文案
- 推荐理由
- 风险提醒

每版文案都保存为 RedBook 草稿，状态为：

- `source = ai`
- `review_status = needs_review`
- `compliance_status = unchecked`

前端显示为卡片，提供：

- `复制标题`
- `复制正文`
- `复制标签`
- `复制封面`
- `通过`
- `拒绝`

### 生成质量要求

Prompt 必须要求：

- 使用中文小红书风格。
- 贴合账号人设。
- 避免禁用词。
- 不承诺绝对效果。
- 不包含自动化、刷量、绕风控相关建议。
- 返回严格 JSON，便于后端解析。

## 隐藏素材功能

本次不删除素材后端和数据库，只在桌面端隐藏左侧 `素材` 导航入口，并不再在仪表盘突出素材指标。

保留原因：

- 以后需要素材库时可以快速恢复。
- 不破坏已有测试和数据结构。

## 运营分析页面

将现有 `发布记录` 页面升级为 `运营分析`。

页面包含三块：

1. 手动发布记录：保留原有发布结果记录能力。
2. 数据看板录入：新增账号级数据看板表单。
3. AI 运营建议：根据人设和数据看板生成建议。

## 数据看板手动录入

### 基础信息

- 账号
- 统计周期：近 7 日、近 30 日、自定义
- 开始日期
- 结束日期

### 指标

- 曝光数
- 观看数
- 点赞数
- 评论数
- 收藏数
- 分享数
- 净涨粉
- 新增关注
- 取消关注
- 主页访客
- 封面点击率
- 视频完播率

### 环比

环比字段可选：

- 曝光数环比
- 观看数环比
- 点赞数环比
- 评论数环比
- 收藏数环比
- 分享数环比
- 净涨粉环比
- 新增关注环比
- 主页访客环比
- 封面点击率环比
- 视频完播率环比

环比输入以百分比文本保存，例如：

```text
-40%
12%
-
```

## AI 运营建议

点击 `生成 AI 运营建议` 后，后端读取：

- 账号档案
- 账号人设
- 最近一条或指定周期的数据看板记录
- 最近草稿和发布记录摘要

AI 输出结构：

- 整体表现总结
- 最大问题
- 可能原因
- 人设匹配度
- 下周内容方向
- 标题/封面建议
- 发布时间和频率建议
- 3-5 条可直接进入草稿页的选题/文案建议
- 风险提醒

前端以卡片形式展示，可复制建议文本。

## 后端数据模型

新增 `dashboard_records` 表，用于保存账号级看板数据。

关键字段：

- `id`
- `account_id`
- `period_type`
- `period_start`
- `period_end`
- `exposure_count`
- `view_count`
- `like_count`
- `comment_count`
- `favorite_count`
- `share_count`
- `net_follower_count`
- `new_follower_count`
- `lost_follower_count`
- `profile_visitor_count`
- `cover_click_rate`
- `video_completion_rate`
- `trend_notes`：JSON 字段，保存各项环比文本
- `created_at`

新增 API：

- `POST /dashboard-records`
- `GET /dashboard-records`
- `GET /accounts/{account_id}/dashboard-records`
- `POST /ai/analyze-dashboard`

## 前端交互

### 草稿页面

保留手动草稿。

AI 区域改为：

- 账号选择
- 主题
- 生成数量
- 补充要求
- `生成 AI 文案`

生成完成后刷新草稿列表。

### 运营分析页面

原 `发布记录` 导航改名为 `运营分析`。

页面保留发布记录表单，并新增：

- 数据看板录入表单
- 数据看板历史列表
- AI 运营建议按钮
- AI 建议结果卡片

## 测试与验收

后端测试：

- 能创建数据看板记录。
- 能按账号列出数据看板记录。
- AI 文案生成支持多版输出。
- AI 运营分析测试不调用真实 OpenAI，通过 monkeypatch 模拟。
- 没有 OpenAI Key 时返回清晰错误。

前端验证：

- TypeScript 通过。
- Vite 构建通过。
- Electron 构建通过。
- Windows 打包通过。

人工验收：

- 左侧不显示 `素材`。
- `草稿` 可根据人设生成多版 AI 文案。
- 每版文案可以复制。
- `运营分析` 可录入截图里的数据看板指标。
- AI 能基于指标输出具体建议。
